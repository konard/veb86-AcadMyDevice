# MyDevice — ObjectARX для AutoCAD 2021

Экспериментальный проект по созданию собственного пользовательского объекта **MyDevice** для AutoCAD 2021 с использованием **ObjectARX**.

## Цель проекта

Проверить на практике возможность создания полноценного пользовательского `AcDbEntity`, который хранит собственные свойства и имеет собственное графическое представление.

Создаваемый объект:

```text
MyDevice
├── Text1
├── Text2
├── BlockName
└── Visibility
```

### Графическое представление

`MyDevice` должен отображать:

* первый MText на основе свойства `Text1`;
* второй MText на основе свойства `Text2`;
* указанный блок AutoCAD;
* состояние Visibility для Dynamic Block.

Тексты являются частью логики `MyDevice` и не должны храниться как отдельные объекты ModelSpace.

## Dynamic Block

Свойство `BlockName` указывает имя блока, используемого внутри `MyDevice`.

Если блок является Dynamic Block, его параметр **Visibility** должен управляться через свойство `Visibility` самого `MyDevice`.

Предполагаемая схема:

```text
MyDevice
    │
    ├── Text1
    ├── Text2
    │
    └── BlockReference
             │
             └── Dynamic Block
                    │
                    └── Visibility
```

Для работы с динамическими свойствами используется API ObjectARX:

```text
AcDbDynBlockReference
AcDbDynBlockReferenceProperty
```

## Свойства в Properties Palette

Пользователь должен иметь возможность изменять:

```text
Text1
Text2
BlockName
Visibility
```

Изменение свойства должно приводить к обновлению графического представления `MyDevice`.

## Проверка прототипа

Необходимо проверить:

1. Создание `MyDevice`.
2. Изменение его свойств через Properties Palette.
3. Отображение двух текстов.
4. Отображение указанного блока.
5. Управление Visibility Dynamic Block через `MyDevice`.
6. Сохранение `MyDevice` в DWG.
7. Закрытие и повторное открытие DWG.
8. Восстановление всех свойств и графики.
9. Корректную работу перемещения, копирования и поворота объекта.

Если `BlockName` указывает на отсутствующий блок, объект должен отображать понятное состояние `BLOCK NOT FOUND`.

## Статус

Проект является **техническим прототипом**.

Основная задача текущего этапа — подтвердить возможность создания собственного объекта `MyDevice` с собственными свойствами, двумя текстовыми представлениями и управляемым Dynamic Block.

После успешного завершения прототипа архитектура может быть расширена до полноценного инженерного объекта Device.

## Этап 1: минимальный пользовательский объект

Реализован минимальный рабочий `MyDevice`:

* класс `MyDevice : AcDbEntity` зарегистрирован как runtime-класс (DXF-имя `MYDEVICE`);
* команда `MYDEVICE` запрашивает точку вставки и создаёт объект в ModelSpace;
* свойства `Text1`/`Text2` (по умолчанию `TEXT1`/`TEXT2`) сохраняются в DWG и DXF;
* объект сам рисует прямоугольник 100×50 и оба текста (в `subWorldDraw()`), отдельные `AcDbText`/`AcDbMText` не создаются;
* поддерживаются перемещение, поворот, равномерное масштабирование, зеркалирование, ручка в точке вставки, команда `LIST`.

```text
 (0,50) ┌──────────────────────┐ (100,50)
        │ TEXT1                │   Text1: базовая точка (5, 30), высота 10
        │ TEXT2                │   Text2: базовая точка (5, 10), высота 10
  (0,0) └──────────────────────┘ (100,0)
        ↑ точка вставки
```

Размеры заданы в единицах чертежа в системе координат объекта, точка вставки — левый нижний угол.

### Структура

```text
MyDevice.sln, MyDevice.vcxproj   проект Visual Studio 2019 (v142, x64) → MyDevice.arx
src/
  StdAfx.h                       заголовки ObjectARX 2021
  MyDevice.h / MyDevice.cpp      класс MyDevice: поля, отрисовка, DWG/DXF
  MyDeviceCommand.h / .cpp       команда MYDEVICE
  acrxEntryPoint.cpp             точка входа: регистрация класса и команды
tests/                           модульные тесты на имитации ObjectARX
experiments/                     вспомогательные скрипты проверки
```

### Сборка

Требуется Visual Studio 2019 (набор инструментов v142, допускается VS 2022 с установленным v142), Windows SDK 10 и ObjectARX 2021 SDK.

1. Укажите путь к ObjectARX 2021 одним из способов:
   * переменная окружения `OBJECTARX2021` (например, `C:\ObjectARX 2021`);
   * свойство MSBuild: `msbuild MyDevice.sln /p:Configuration=Release /p:Platform=x64 /p:ObjectArxDir="C:\ObjectARX 2021\"`;
   * по умолчанию используется `C:\ObjectARX 2021\`.
2. Соберите конфигурацию `Release|x64` (или `Debug|x64`).
3. Результат: `bin\x64\Release\MyDevice.arx`.

Обе конфигурации используют `/MD` без `_DEBUG`, как требует ObjectARX: отладочная информация в `Debug` есть, но с отладочной CRT модуль в AutoCAD не загрузится.

### Загрузка и проверка в AutoCAD 2021

1. `APPLOAD` (или `ARX` → `Load`) → выбрать `MyDevice.arx`. В командной строке появится `MyDevice загружен. Команда: MYDEVICE.`
2. `MYDEVICE` → указать точку. Появится прямоугольник 100×50 с текстами `TEXT1` и `TEXT2`.
3. `LIST` по объекту показывает класс, точку вставки и тексты.
4. Сохранить чертёж (`QSAVE`), закрыть, снова загрузить `MyDevice.arx` и открыть чертёж — объект на месте с теми же текстами.
5. `DXFOUT` → `DXFIN` в новый чертёж — объект также восстанавливается.

Если открыть чертёж без загруженного `MyDevice.arx`, объекты будут показаны как прокси (графика сохраняется, редактирование запрещено). Модуль не выгружается командой `ARX` → `Unload`, пока открыт сеанс AutoCAD, — это защищает чертежи с объектами `MyDevice` от обращения к выгруженному коду.

### Формат хранения

DWG: версия формата (`Int16`), точка вставки, направление оси X, нормаль, масштаб, `Text1`, `Text2`.

DXF (подкласс `MyDevice`):

| Код | Значение |
|-----|----------|
| 70  | версия формата (1) |
| 10  | точка вставки |
| 11  | направление оси X |
| 40  | масштаб |
| 210 | нормаль |
| 300 | Text1 |
| 301 | Text2 |

Чертёж, сохранённый более новой версией формата, открывается с объектом-прокси, а не с повреждёнными данными.

### Тесты

Модульные тесты собирают исходники `src/` без изменений против минимальной имитации ObjectARX (`tests/mock`) и запускаются на Linux/macOS/Windows без AutoCAD:

```sh
cmake -S tests -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Проверяются: регистрация класса и команды, значения по умолчанию, отрисовка (один замкнутый контур 100×50 и два текста), сохранение и чтение DWG/DXF (включая кириллицу и чужие группы DXF), преобразования, ручки и команда `MYDEVICE` (включая ПСК и отмену). Те же тесты запускаются в GitHub Actions (`.github/workflows/tests.yml`).

`experiments/mutation-check.sh` вносит в копию исходников типичные ошибки и проверяет, что тесты их обнаруживают. `experiments/syntax-check-real-sdk.sh` компилирует исходники с настоящими заголовками ObjectARX 2021 через `zig c++` (нужен свой экземпляр SDK, см. комментарий в скрипте).

### Ограничения этапа 1

* Тексты задаются только из кода (`setText1()`/`setText2()`); Properties Palette, `BlockName` и `Visibility` — следующие этапы.
* Неравномерное масштабирование (`eCannotScaleNonUniformly`) не поддерживается.
